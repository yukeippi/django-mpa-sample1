# 仕様: 部門の親子関係を設定する

> この仕様は作成日時(ファイル名の先頭)の時点の記録です。完了後は更新しません。現在の挙動の正本はコードとテストです。

## 部門詳細画面(GET /departments/<pk>/)
- 親部門(会社名 / 部門名)が表示される。親部門が無い場合は「親部門はありません」と表示される
- 子部門(この部門を親部門にしている部門)の一覧が、部門名順に表示される。子部門が無い場合は「子部門はありません」と表示される
- 全社管理者にだけ、「親部門を変更」が表示される

## 親部門の変更(/departments/<pk>/hierarchy/edit/)
- 親部門の選択肢は、同じ会社の部門のうち自分以外で、部門名順に並ぶ。先頭に「なし」がある
- 変更フォームを開くと、今の親部門が選ばれた状態になっている(親部門が無い場合は「なし」)
- 親部門を選んで保存すると、部門詳細画面にリダイレクトされ、「親部門を変更しました。」と表示される
- 「なし」を選んで保存すると、親部門が無い状態になる
- 選択肢に無い部門(別の会社の部門、自分自身)を送信してもエラーになり、親部門は変わらない
- 別の会社の部門は親部門にできない。画面を通らない保存でも、full_clean()で「親部門には同じ会社の部門を指定してください。」のエラーになる
- 自分自身は親部門にできない(画面を通らない保存でもDBで守る。既存の制約)

## 部門の編集(会社の変更)
- 親部門または子部門がある部門は、会社を変更できない(「親部門・子部門がある部門は会社を変更できません。先に親子関係を外してください。」を会社の欄に表示し、部門は変わらない)。画面を通らない保存でも、full_clean()で検証する
- 親部門も子部門も無い部門は、これまでどおり会社を変更できる
- 会社を変えずに部門名だけを変更する場合は、親部門・子部門があっても変更できる

## 権限
- 親部門を変更できるのは全社管理者だけ(全社管理者の管理グループ(is_admin)のメンバー)
- 全社管理者でないユーザーが変更フォームを開く・保存すると403になり、親部門は変わらない
- 存在しない部門は404
- 未ログインの場合はログインページにリダイレクトされる

## 対象外
- 親子関係の循環(子や孫を親部門にすること)は防がない(既存の設計どおり。権限の判定は1階層しか見ないため、循環があっても止まらない)
- 部門一覧での親子関係の表示(ツリー表示など)
